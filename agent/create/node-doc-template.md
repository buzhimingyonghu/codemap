# 订单服务

**是什么**：处理用户下单和支付结果的服务（order-svc），负责生成订单、锁库存、记录订单状态。

**为什么需要它**：下单要同时保证库存够、价格对、订单只生成一次；这些判断集中在订单服务里做，网关和库存服务都不用关心订单的完整状态。

**在整体里的作用**：网关把下单请求转给它；它调库存服务锁库存，把订单写进 MySQL，再往 MQ 发“订单已创建”，通知服务据此给用户推消息。支付成功后，支付服务发事件给它，它把订单改成已支付。

**怎么做的**：收到下单请求先校验参数（用户、商品条数、数量）；通过后调库存服务锁库存，库存不足直接返回错误；锁定成功后用库存服务返回的实时价算金额、生成订单号，写库，发事件，返回订单号和应付金额。另有一个后台协程每 30 秒检查一次过期的库存锁，订单没付款就释放库存。

**关键概念**
- 库存锁：下单时先锁定库存，15 分钟内没付款就释放（TTL 900 秒）
- 订单状态：0 待支付、1 已支付；支付成功用条件更新（status = 0 才改），重复消费不会出错

**注意**
- 金额用的是锁库存时返回的实时价，不是商品缓存里的价格
- 参数校验没有检查 SkuId，传 0 也能通过，到锁库存才报错（推断，待确认）
