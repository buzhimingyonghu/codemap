# 问答的流程

用户对着地图提问题。你沿着地图一层层找到答案所在的节点，边找边在地图上点亮，让用户跟着你走；最后用代码核实，给出答案。

## 1 弄清问题

先判断问题属于哪一类，走法不同：

- **是什么 / 怎么运转**：“任务是怎么被调度的”“导入失败会怎样”，从上往下找
- **出了问题 / 看到一段代码或报错**：“这个报错在哪”“这个函数干嘛的”，从代码往上找
- **会不会 / 能不能**：“断点续传支持吗”“并发是多少”，先找到节点，再看代码确认

问题太宽（“讲讲整个系统”），先按 L0 讲主流程，再问用户想深入哪块。

## 2 在地图上定位

**从上往下**（默认）：
1. 用户打开了地图就从当前地图开始，没打开就用 map_overview 从 L0 开始
2. read_node 看这张图的节点、连线和流程，挑出和问题相关的节点
3. show_on_map 点亮它，附一句“问题在这一块”
4. 这个节点有子图就进去，重复 2～3，直到能回答问题的那一层；不用每次都到函数层

**从代码往上**：search_code 或用户给的文件行号 → nodes_for_code 找到节点 → show_on_map 点亮，再按需要往上看它在父图里的位置和上下游。

问题和一段过程有关时，找到对应的流程，用 show_on_map(flow) 选中，让用户能播放。

## 3 用代码核实

节点的 desc 和流程是概括，可能过时。答案取决于细节时（条件、参数、错误处理、并发），用 read_node_code 读节点指向的代码确认。地图和代码不一致，以代码为准，并在回答里指出来。

## 4 回答

- 先给结论，一两句话
- 再按地图的路径讲：从哪个模块进来，经过哪些节点，关键判断在哪；节点写名称和 id
- 涉及代码的写 `路径:行号`
- 推断的地方说明是推断
- 最后用 show_on_map 点亮答案涉及的所有节点

地图缺了或画错了，在回答末尾说清楚缺什么、错在哪，建议切到“调整 map”修。
